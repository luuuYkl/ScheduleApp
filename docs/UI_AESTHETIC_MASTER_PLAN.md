# ScheduleApp 界面美学与产品布局「理想态」蓝图

> 角色视角：软件界面美学大师 + 资深产品经理

## 1. 当前界面基调评估（优点与问题）

### 现有优点
- 已有明暗主题变量体系，且语义化程度较高（`--bg-main`、`--text-secondary`、`--ai-main` 等），说明项目具备系统化设计基础。
- 全局有固定顶部栏与底部导航，移动端导航模型明确。
- 视觉风格方向清晰：偏「AI 感」冷色、柔和玻璃态与低对比层级。

### 关键问题
- 全局样式文件出现明显拼接/损坏痕迹（重复片段、截断语句、混入注释残片），会导致视觉不可预期、维护困难和主题行为不稳定。
- 头部/底部使用固定定位但内容容器策略相对单一，信息密度高时容易产生“可用空间被挤压”的感受。
- 缺少统一的页面布局模板（Dashboard、List、Detail、Form 四类结构未抽象），页面间体验一致性可能不足。

## 2. 「最完美样式」应达成的审美目标

### 视觉关键词
- **克制**：不过度炫技，动画轻，层级清晰。
- **秩序**：8pt 栅格 + 明确间距节奏（8/12/16/24/32）。
- **温度**：在效率工具里保留轻微情绪设计（柔和高亮、低饱和状态色）。
- **可信**：文本对比、状态反馈、错误提示必须稳定且可读。

### 风格结论
建议采用 **「Calm Intelligence」设计语言**：
- 基底低饱和灰阶（避免纯黑纯白）。
- AI 强调色只用于关键动作与高价值信息（占比 < 12%）。
- 全局圆角统一 12（容器）/8（控件）/16（浮层）。
- 阴影以“贴边光晕 + 极浅投影”替代重投影。

## 3. 「最完美布局」信息架构

## 3.1 全局框架（推荐）
- **Desktop（≥1024）**：
  - 顶部：品牌 + 全局搜索 + 快捷创建 + 用户菜单
  - 左侧：一级导航（首页/日历/日志/统计/设置）
  - 主区：内容
  - 右侧（可选）：AI 助手与上下文建议
- **Tablet（768-1023）**：
  - 顶部保留，左侧导航折叠为抽屉
- **Mobile（<768）**：
  - 顶部精简（标题 + 快捷入口）
  - 底部 Tab 固定（3~5 项）
  - 二级导航收进页面内 segmented control

## 3.2 页面模板（必须产品化）
- **Home 仪表盘**：
  - 第一屏：今日关键摘要（3~5 卡）
  - 第二屏：时间轴（今日/本周）
  - 第三屏：AI 建议（仅 1 主建议 + 2 次建议）
- **Calendar 日历**：
  - 顶部日期条 + 视图切换（日/周/月）
  - 主体优先展示“可执行块”，减少装饰
- **Log 日志**：
  - 默认时间线 + 筛选器吸顶
  - 每条日志支持“关联计划/标签/情绪”三要素
- **Profile/Settings**：
  - 两栏式（菜单 + 内容）
  - 敏感操作单独分区，避免误触

## 4. 组件层面的理想规范

### 4.1 卡片（Card）
- 内边距：16（移动）/20（桌面）
- 边框：1px `var(--border-subtle)`
- Hover：只允许 `translateY(-1px)` + 阴影轻微增强
- 不同信息密度使用三种卡片：Summary / Content / Action

### 4.2 按钮（Button）
- 仅保留 3 个等级：Primary / Secondary / Tertiary
- Primary 只在“下一步主路径”出现，单屏最多 1~2 个
- 禁用态透明度不低于 40%，并且不可点击

### 4.3 表单（Form）
- 输入高度统一 40（移动）/44（桌面）
- Label 与帮助文案强制同轴对齐
- 错误信息就近展示，不依赖 toast

### 4.4 导航（Navigation）
- 当前激活项必须有**双重提示**：颜色 + 形态（底条/填充）
- 底部导航文案保持 2~4 字，避免截断

## 5. 动效与交互节奏（高级感关键）

- 全局动效时长：
  - 微交互 120~180ms
  - 容器过渡 200~260ms
- 曲线统一：`cubic-bezier(0.2, 0.8, 0.2, 1)`
- 避免大面积 blur + 阴影叠加导致的“糊感”
- 页面切换优先淡入平移，不做复杂 3D

## 6. 可访问性与国际化（产品成熟度关键）

- 正文最小字号 14，辅助信息最小 12
- 文本对比度：正文至少 WCAG AA（4.5:1）
- 焦点态必须可见（键盘导航）
- 中文场景建议优先系统字体，英文数字可混用 Inter

## 7. 建议的落地路线图（两周冲刺）

### Sprint 1（基础统一）
1. 清理并重建 `src/style.css`（去除损坏片段）
2. 定义 Design Tokens（颜色/圆角/阴影/动效/间距）
3. 完成 App Shell（顶部/侧边/底部）的响应式重构

### Sprint 2（体验拉齐）
1. 抽象 4 类页面模板与 8~12 个核心组件
2. 建立「状态可视化标准」（空态/加载/错误/成功）
3. 上线前做一次深色模式与移动端可用性验收

## 8. 一句话结论

这个项目的“最完美样式和布局”不是更炫，而是**更统一、更稳定、更有节奏**：
以语义化 Token 为底座，以响应式 App Shell 为骨架，以轻量 AI 强调为记忆点，最终形成一个兼顾效率与气质的日程产品体验。
